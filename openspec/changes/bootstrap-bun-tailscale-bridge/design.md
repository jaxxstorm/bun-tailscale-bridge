## Context

This bootstrap delivers connectivity, not an agent integration. Bun manages a Go subprocess because it cannot import `tailscale.com/tsnet` directly. The helper embeds an independent userspace Tailscale node; consumers such as `jaxxstorm/opencode-aperture` own destinations, application protocols, and plugin behavior.

## Goals / Non-Goals

**Goals:**

- Manage an independent userspace node without root, TUN, host VPN changes, or a host Tailscale daemon.
- Expose Tailscale's supported SOCKS mechanism and an authenticated HTTP/CONNECT proxy for explicit per-request Bun native fetch, with shared lifecycle, private state, and private control pipes.
- Package pinned helpers and prove behavior with secret-free offline tests and optional live evidence.

**Non-Goals:**

- A fixed-origin HTTP gateway, custom HTTP parser, TLS interception, or helper-owned redirect/retry policy beyond not following or replaying requests.
- A strict tailnet-only destination API or egress firewall. Non-tailnet host DNS/direct routing remains upstream behavior.
- Agent SDKs, plugin implementations, OAuth, discovery policy, global network interception, or universal sandbox compatibility.
- Host VPN setup, exit-node/subnet advertisement, inbound tailnet services, or package publication.

## Decisions

### 1. Bun library plus a Go tsnet helper

Use one helper per bridge, launched with `Bun.spawn` without a shell. Call `tsnet.Server.Up` before supported `tsnet.Server.Loopback`; retain its built-in SOCKS listener and add a separate authenticated HTTP/CONNECT listener in Go. Reuse Tailscale `net/connectproxy` for tunnel handling and standard Go HTTP facilities for forwarding, rather than writing an HTTP parser. Suggested layout remains `src/`, `helper/`, `test/`, `examples/`, and `scripts/`, with Go tests beside implementation.

Pin Go 1.26.2 and `tailscale.com` 1.96.5. Tailscale 1.102.3 requires Go 1.26.6 and is not compatible with the chosen Go pin. Pin Bun 1.4.2 and TypeScript 5.9.3. Use `@types/bun` 1.4.1, the latest published types at the upgrade because 1.4.2 types were unavailable; the runtime remains 1.4.2. Select the project runtime through `.bun-version` and the command environment, without upgrading global Bun. A subprocess avoids FFI and keeps the Go runtime isolated; invoking the system Tailscale CLI would violate the architecture.

### 2. Small explicit public API

```ts
type BridgeOptions = {
  hostname: string;
  authKey?: string;
  startupTimeoutMs?: number; // Default: 60_000
  signal?: AbortSignal;
  onAuthRequired?: (event: { url: string }) => void;
  helperPath?: string;
} & (
  | { stateDir: string; ephemeral?: false }
  | { stateDir?: never; ephemeral: true }
);

type ProxyInfo = {
  host: "127.0.0.1";
  port: number;
  username: "tsnet";
  password: string;
};

declare function createBridge(options: BridgeOptions): Promise<{
  proxy(): ProxyInfo;
  httpProxyURL(): string;
  close(): Promise<void>;
}>;
```

Require a nonempty hostname, exactly one state mode, a positive finite startup timeout, and absolute `stateDir`/`helperPath` when supplied; reject invalid options before enrollment. `signal` cancels startup, not later consumer requests. `proxy()` synchronously returns a fresh descriptor while ready, with an ephemeral TCP port and the 32-hex-character random 128-bit SOCKS password generated by tsnet. Do not replace the SOCKS credential or expose any LocalAPI credential. `httpProxyURL()` synchronously returns `http://tsnet:<password>@127.0.0.1:<port>` for a separate ephemeral listener, using an independently generated random 128-bit, 32-hex-character per-instance HTTP password. Both accessors fail locally after failure/close; previously returned endpoints become unusable when the helper stops. There is no bridge request wrapper or destination configuration.

### 3. Versioned private control channel

Use newline-delimited JSON on inherited stdin/stdout, exclusively for control, with a protocol version and maximum 64 KiB frames. Send explicit node options and auth keys on the private pipe, never argv, persisted transcripts, or ambient `TS_*` configuration. Ready frames carry both SOCKS and HTTP proxy endpoint data, never the LocalAPI credential. Validate both numeric-loopback addresses, distinct ports, usernames, password shapes/separation, and protocol version before accepting readiness; construct the public HTTP URL only from validated data. Unknown, malformed, oversized, incompatible frames, premature EOF, and child exit fail startup with stable sanitized codes. Keep raw tsnet logs off stdout and out of diagnostics; use allowlisted status/errors and deliver login URLs only to the opt-in callback. Never log credential-bearing proxy URLs.

The parent closes stdin on disposal. The helper handles EOF (including parent death), shutdown commands, and termination signals by closing both proxy listeners, active SOCKS connections, HTTP forwarding work/transports, and tracked CONNECT tunnels, then closing tsnet and releasing state resources. Track hijacked CONNECT connections explicitly because HTTP server shutdown alone does not close them. `close()` is idempotent. Allow five seconds for graceful shutdown, then terminate an unresponsive helper and escalate to forced termination if necessary. Clean partial startup on all failures, including failure of the second listener. Do not automatically restart failed helpers or establish replacement direct connections; this lifecycle rule does not alter normal upstream non-tailnet routing.

### 4. Explicit identity and readiness

Persistent mode requires an absolute private directory (`0700`) and owner-only identity files (`0600`). Reject unsafe ownership/permissions and symlinked state locations. Hold an OS-backed exclusive state-directory lock for the helper lifetime. Separate directories mean separate identities; persistent close never deletes identity or logs out.

Ephemeral mode uses a bridge-owned private temporary directory and tsnet ephemeral enrollment, mutually exclusive with `stateDir`. Remove temporary state on normal shutdown and partial-start cleanup without deleting caller-owned state. Crashes may leave temporary files; closing locally does not promise immediate control-plane node deletion.

Reuse enrolled state first; otherwise use an explicit auth key or structured interactive authentication via `onAuthRequired({ url })`. Obtain auth state and URLs through tsnet's local client, not log parsing. Without a key or callback for an unenrolled identity, fail with `AUTH_REQUIRED`. Bound the complete startup by `startupTimeoutMs` (default 60,000 ms) and honor startup cancellation, including during enrollment. Resolve only after `Up` succeeds and both the Loopback SOCKS endpoint and separate HTTP/CONNECT endpoint are listening. Readiness does not prove destination reachability or policy authorization.

### 5. SOCKS, HTTP/CONNECT, and honest routing

`Server.Loopback` binds numeric IPv4 loopback on an ephemeral port. Its listener multiplexes the upstream authenticated SOCKS service and authenticated LocalAPI using separate credentials. Return host `127.0.0.1`, parsed port, username `tsnet`, and the SOCKS password exactly as supplied by tsnet; discard the separate LocalAPI credential from bridge-facing data. It must not appear in IPC, public types, examples, or diagnostics. Do not implement a LocalAPI relay or expose the helper's internal local client.

The upstream SOCKS server dials through `UserDial`. Known tailnet destinations use the embedded userspace stack subject to Tailscale policies, without host daemon, TUN, or root. For non-tailnet destinations upstream retains host DNS and direct dialing. Selecting this documented mechanism deliberately accepts those semantics: the bridge is not an egress firewall, does not restrict destinations, and cannot claim that all traffic or all DNS stays within the tailnet. No custom strict dialer replaces production `UserDial`.

The HTTP proxy binds only `127.0.0.1` on its own ephemeral port and requires HTTP Basic proxy authentication with username `tsnet` and its independent password on every request, including every CONNECT and each request on a reused connection. Missing/malformed/wrong credentials return 407 with a Basic `Proxy-Authenticate` challenge before any destination dial. Neither SOCKS nor LocalAPI credentials authorize HTTP proxy access.

Use `tsnet.Server.Dial` directly or a hop through the built-in SOCKS service for both HTTP forwarding and CONNECT; retain upstream routing semantics rather than adding an independent host dialer, ambient HTTP proxy chaining, or a destination allowlist. Known tailnet destinations use userspace networking; non-tailnet host DNS/direct behavior remains available upstream. Proxy-side hostname dialing is not a promise that all DNS remains in the tailnet.

For plain HTTP, accept absolute-form HTTP targets and forward to the requested remote authority while preserving method, path/query, body, remote Host, application Authorization/cookies, status, and ordinary end-to-end headers. Always remove proxy credentials and standard hop headers; remove additional Connection-nominated fields when Go exposes that metadata. Go consumes response Connection headers containing close, so arbitrary additional nominated fields can survive on final or informational responses. Discard request/response trailers rather than support trailer-dependent protocols; no custom HTTP parser is added. Stream with bounded buffers/backpressure and incremental flushing, propagating disconnect/cancellation. Use standard Go HTTP forwarding without following redirects or replaying requests, including disabling transport retry paths that could replay. Return upstream redirects unchanged for the consumer's fetch policy; do not impose the former fixed-origin redirect rejection.

For HTTPS, authenticate CONNECT, validate its host:port authority, and dial through the same tsnet-backed path. After successful CONNECT, relay opaque bytes bidirectionally using reusable `tailscale.com/net/connectproxy` tunnel handling with lifecycle tracking around it. TLS stays end-to-end between Bun and the remote server, including original destination SNI and certificate/hostname verification; the helper does not terminate TLS or inspect tunneled headers. Strip proxy credentials from outer forwarding, not from opaque tunnel payload. Consumer-selected URLs remain remote URLs, never rewritten to a local gateway origin.

Consumers own request selection, destinations, application auth, TLS trust, timeouts, redirects, retries, and cancellation. SOCKS stays a byte-level interface; the HTTP proxy adds only standard forward-proxy behavior. Neither interface intercepts traffic globally. Closing the helper terminates connections; consumers own response consumption and error handling.

Historical Bun 1.3.14 evidence includes fixed JSON/byte HTTPS requests and incremental SSE responses, but streamed HTTPS request bodies through CONNECT stalled even with an explicit length. The exact concurrent upload regression delivered zero bytes across four requests on 1.3.14 and passed unchanged on 1.4.2. Direct Bun HTTPS streaming and curl streaming through the same proxy also succeeded on the historical baseline. Upstream [issue #33918](https://github.com/oven-sh/bun/issues/33918) and merged [PR #32635](https://github.com/oven-sh/bun/pull/32635) identify the runtime fix, released in [Bun 1.4.0](https://bun.sh/blog/bun-v1.4.0) and included in 1.4.2. Upgrade Bun without changing the Go helper or adding custom full-body buffering or another HTTP transport; enable the regression test on the supported runtime.

Require native HTTPS CONNECT uploads to deliver an initial chunk before the complete request body is produced, preserve body integrity across concurrent multi-megabyte requests, and stop producer/upstream work on mid-upload abort. The concurrent regression and two additional native tests (first 32 KiB delivered before opening the producer gate, and mid-upload abort) passed 10 local macOS arm64 repetitions on 1.4.2. Keep this targeted evidence separate from the historical 1.3.14 full-suite ledger; final new-runtime full checks, build/package results, and counts remain for the main verifier to record. No live or additional native-platform evidence is implied.

### 6. Consumption stays agent-independent

Bun 1.4.2 native fetch uses the HTTP proxy explicitly per request; it does not need SOCKS support or an additional JavaScript HTTP adapter:

```ts
const response = await fetch(remoteURL, {
  proxy: bridge.httpProxyURL(),
  headers: { Authorization: "Bearer synthetic-application" },
  signal: AbortSignal.timeout(10_000),
  redirect: "manual",
});
```

The plugin chooses which requests need tailnet connectivity and supplies `proxy` on those calls while retaining each original remote URL. Requests without that option remain on their existing path. Do not replace global fetch, set proxy environment variables, mutate agent config, or export a bridge fetch wrapper. Consumers choose native fetch redirect behavior; the helper never follows redirects itself. SOCKS remains available through `proxy()` for clients that already support it, with no mandated client dependency or URI format.

An agent-independent Aperture example requests `/api/providers` and streams `/codex/responses` through native fetch with consumer-selected URLs and synthetic credentials, normal HTTPS verification, explicit cancellation/redirect choices, and close after response consumption. It requires no additional client packages, adapter, SDK, or plugin implementation. Never log credential-bearing proxy URLs or claim existing plugins work unchanged. Hosted/sandboxed environments must permit helper execution, outbound networking, and loopback access.

### 7. Local packaging and validation

Produce ESM, TypeScript declarations, and version-matched executable helpers for `darwin-arm64`, `darwin-x64`, `linux-arm64`, and `linux-x64`, bundled in one private package. Resolve the exact asset or explicit absolute development `helperPath`; reject unsupported platforms, missing/non-executable assets, and incompatible protocols before enrollment. No runtime downloads, compilation, Go installation, or system Tailscale requirement.

Offline verification uses fake tsnet lifecycle/control helpers for enrollment, readiness, failure, and state tests. Retain real pinned upstream SOCKS server tests with an injected dialer for authentication, hostname forwarding, byte transfer, and teardown. Extend lifecycle/protocol tests for two-endpoint readiness, separate HTTP credentials, second-listener failure, and active CONNECT cleanup. Go HTTP proxy tests exercise the real forwarding/tunnel implementation with injected dialing for 407-before-dial authentication, absolute-form forwarding, credential/hop-by-hop removal, application auth preservation, opaque CONNECT, redirects without follow, no replay, streaming, and shutdown.

Cross-language tests run Bun native fetch against the Go HTTP proxy with fake lifecycle and local HTTP/HTTPS fixtures, without enrollment or extra JavaScript client dependencies. Verify GET/POST, original remote URL/Host, hostname/port dial arguments, TLS chain/hostname verification and destination SNI, incremental SSE, abort teardown, consumer-selected redirect behavior, and that unrelated requests without `proxy` remain direct. Distinguish simulation from live upstream routing: no injected-dialer test proves live tailnet policy or non-tailnet egress isolation. Keep LocalAPI credentials out of public data and all credentials out of diagnostics.

Inspect the packed artifact in a clean Bun consumer, including all four assets, exports/types, executable permissions, and launch of the native bundled helper without enrollment. Exclude state, secrets, and local agent configuration. CI runs secret-free typechecks, Bun/Go tests, supported race checks, builds, and package verification. Distinguish cross-compilation from actual native runtime evidence. Optional live tests cover daemonless non-root tailnet access, MagicDNS, policy-denied/unreachable known-tailnet targets, identity reuse, and cleanup; they do not assert denial of non-tailnet destinations. Skip explicitly without opt-in and credentials.

## Risks / Trade-offs

- Both proxies retain upstream non-tailnet host networking; consumers needing egress restrictions must enforce them outside this bridge.
- SOCKS and LocalAPI share a port; credential separation and never exposing the LocalAPI password are essential. Loopback auth is not protection against same-user compromise.
- The HTTP proxy URL is a secret; independent credentials, authentication on every request, and proxy-header removal prevent accidental reuse or forwarding. HTTPS payload stays opaque, while plain HTTP is visible to the helper.
- Binary size and subprocess overhead are accepted in exchange for avoiding native FFI and runtime toolchains.
- Pinned upstream behavior needs review on upgrades; Bun client compatibility must be tested, not inferred from Node APIs.
- Long-lived processes require explicit close, EOF cleanup, locking, and deadlines. Raw upstream logs are suppressed at the bridge boundary; upstream Tailscale telemetry is documented separately, not claimed absent.

## Migration Plan

There is no shipped API to preserve. Build and test locally, verify the packed artifact, then optionally validate live connectivity with disposable credentials. External consumers select native fetch requests for the HTTP proxy or adopt SOCKS in their own repositories. Rollback stops the bridge and removes integration without deleting persistent identity or application credentials; operators revoke tailnet nodes separately.
