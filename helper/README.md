# Go Proxy Helper

Standalone module, pinned to **Go 1.26.2** and **tailscale.com v1.96.5**.
Tailscale v1.102.3 requires Go 1.26.6 and is not compatible with this toolchain.
Production uses public `tsnet.Server.Up` and `tsnet.Server.Loopback` for SOCKS,
plus an authenticated HTTP forward/CONNECT listener using `tsnet.Server.Dial`.
CONNECT tunneling reuses `tailscale.com/net/connectproxy.Handler`; plain HTTP
uses Go's `httputil.ReverseProxy` and `http.Transport`. There is no fixed-origin
gateway, replacement SOCKS server, or strict resource dialer. No system
Tailscale installation, root, or TUN is required.

## Build And Test

Run from `helper/`:

```sh
GOTOOLCHAIN=local go mod tidy
GOTOOLCHAIN=local go build -tags=ts_omit_webclient -o bin/bridge ./cmd/bridge
GOTOOLCHAIN=local go test ./...
GOTOOLCHAIN=local go test -race ./...
GOTOOLCHAIN=local go vet ./...
```

The production executable is `helper/bin/bridge` relative to the repository
root. Package only binaries built from `./cmd/bridge`. All runtime configuration
arrives on stdin; there are no credential arguments or test-dial switches.
The shared-fixture tests read the repository's `fixtures/protocol.json`.

## Private Protocol

Use private inherited pipes. Send one JSON object per newline, at most 65,536
UTF-8 bytes excluding the newline. Unknown fields/types, duplicate object keys,
missing required fields, invalid values, incompatible versions, and unfinished
frames are rejected. There are no progress or closed status frames.

Start, with exactly one state mode:

```json
{"type":"start","version":1,"options":{"hostname":"my-bridge","ephemeral":true,"startupTimeoutMs":60000,"interactive":false}}
```

Persistent mode instead sets `ephemeral:false` and an absolute `stateDir`.
`authKey` is optional and must be explicitly supplied through this pipe. The
helper requires a 1-63 character DNS-label hostname and an integer startup
timeout from 1 through 2,147,483,647 milliseconds. Defaults are the parent's
responsibility. Neither `origins` nor `requestTimeoutMs` is accepted.

Ready after node readiness and both proxy listeners are established:

```json
{"type":"ready","version":1,"proxy":{"host":"127.0.0.1","port":12345,"username":"tsnet","password":"00000000000000000000000000000000"},"httpProxy":{"host":"127.0.0.1","port":12346,"username":"tsnet","password":"11111111111111111111111111111111"}}
```

The example passwords are synthetic. The SOCKS password is generated by tsnet;
the HTTP password is generated independently with `crypto/rand`. Both have 128
random bits represented by 32 lowercase hex characters. Protect both
descriptors as secrets; never log credential-bearing proxy URLs. The
LocalAPI credential returned separately by tsnet is discarded and is never
included in the control protocol. The built-in listener still multiplexes
LocalAPI, which requires its separate password and `Sec-Tailscale: localapi`.

Interactive enrollment is allowed only when `interactive:true`. Structured
LocalClient notifications produce this event, never log parsing:

```json
{"type":"auth_required","version":1,"url":"https://login.tailscale.com/a/synthetic"}
```

Raw upstream failures are replaced with allowlisted codes:

```json
{"type":"error","version":1,"code":"AUTH_REQUIRED"}
```

Close with `{"type":"close","version":1}`, stdin EOF, SIGINT, SIGTERM, or
SIGHUP. A second start or invalid later frame fails the instance. Normal disposal
exits zero without a final frame; failures exit nonzero. The process is never
restarted automatically.

## Lifecycle And State

- Persisted enrollment is reused by tsnet; explicit auth keys are not used to
  force re-enrollment. A new identity without a key or interactive opt-in fails
  with `AUTH_REQUIRED` when the structured backend state requires login.
- Persistent directories must be owned by the effective user and mode `0700`;
  regular identity/state files must be owned by that user and mode `0600`.
  Symlinks inside state, a symlink as the supplied final directory component,
  hardlinked files, special files, and unsafe parent write permissions fail.
- Trusted parent aliases such as macOS `/var -> /private/var` are resolved,
  rather than rejecting every path that traverses a system symlink. Resolved
  ancestors must belong to root or this user and not be writable by others,
  except sticky directories such as `/tmp`.
- `.bridge.lock` uses an OS-backed nonblocking exclusive `flock`. The lock file
  is never removed or replaced during persistent close. Advisory locks require
  a filesystem with working Unix lock semantics; use a local state directory.
- Ephemeral state uses a private bridge-owned temporary directory. Normal close
  and cooperative startup failures remove it; caller-owned directories are
  never recursively removed. Persistent close neither deletes identity nor
  logs out. Remote ephemeral-node deletion is controlled by Tailscale.
- Startup is bounded even if synchronous upstream initialization gets stuck.
  Cleanup waits at most four seconds before the executable exits; while a node
  is still initializing, its directory is not unlocked or deleted. Such forced
  exits/crashes may leave private temporary state. Process exit is the final
  boundary for all accepted SOCKS tunnels, including host-routed connections.
  The HTTP listener tracks both accepted and upstream connections so close also
  terminates HTTP streams, in-progress dials, and hijacked CONNECT tunnels before
  closing tsnet.
- The executable removes `TS_*`, `TSNET_*`, and `TAILSCALE_*` environment settings
  before creating a node and resets registered environment knobs. The parent
  must also filter these before spawn, since dependency package initialization
  happens before Go `main`. Do not inherit secrets into the helper environment.
- After entering `main`, raw stdout/stderr file descriptors and standard logs
  are redirected to the null device; only the duplicated private protocol
  writer remains. Both tsnet log callbacks are silent. This is not a promise
  that Tailscale's own upstream telemetry or private state logs are absent.

Readiness proves node readiness, not that a destination is reachable or allowed.
Both proxy endpoints retain upstream `UserDial` semantics: known tailnet
destinations use userspace Tailscale routing and policy; other names/destinations
can use host DNS and networking. This is **not a tailnet-only egress firewall**.
Clients own their destinations, TLS validation, application credentials,
redirects, retries, request timeouts, and streaming cancellation. Use a SOCKS
client that forwards destination hostnames to the proxy (usually `socks5h`).
The Bun 1.4.2 native-fetch contract uses the separate HTTP proxy, not SOCKS.

## HTTP And CONNECT

Use the separate HTTP descriptor to construct
`http://tsnet:<http-password>@127.0.0.1:<http-port>`. The Bun library's
`httpProxyURL()` supplies this URL to explicitly selected requests:

```ts
await fetch(remoteURL, { proxy: bridge.httpProxyURL() });
```

The original remote URL remains unchanged. No global fetch or proxy environment
configuration is required. HTTP proxy authentication uses `Proxy-Authorization:
Basic ...` on every request, including reused client connections and CONNECT.
Missing/invalid credentials receive 407 and a Basic challenge before dialing.
SOCKS and LocalAPI passwords are not the HTTP credential.

Plain HTTP accepts only absolute-form `http://host[:port]/path?query` requests.
CONNECT requires a valid `host:port` authority and tunnels bytes without TLS
termination. Origin-form/LocalAPI requests, URL credentials/fragments, CONNECT
bodies, browser Origin/Fetch Metadata headers, and HTTP upgrades are rejected.
HTTP application Authorization/cookies and the remote Host are preserved.
Proxy credentials, standard hop-by-hop and forwarding headers, and trailers
are not forwarded. Informational responses are filtered before forwarding too.
Responses stream incrementally; redirects are returned, not
followed. Upstream connection reuse is disabled to prevent Go transport replay.
HTTP dials/response-header waits are bounded at 30 seconds; the reused upstream
CONNECT handler bounds dialing at 15 seconds. Healthy streams have no total
duration limit. Consumer TLS verification, redirects, and retries remain the
consumer's responsibility.

Native Bun 1.4.2 supports streamed HTTPS request bodies through CONNECT. The
Bun 1.3.14 upload stall was a runtime regression tracked in
[oven-sh/bun#33918](https://github.com/oven-sh/bun/issues/33918), fixed by merged
[PR #32635](https://github.com/oven-sh/bun/pull/32635) in
[Bun 1.4.0](https://bun.sh/blog/bun-v1.4.0) and included in 1.4.2. No Go helper
change, custom buffering, or alternative transport is needed. Native tests
cover concurrent upload integrity, early 32 KiB delivery before the producer
gate opens, and mid-upload abort stopping producer/upstream work. See
[validation](../docs/validation.md) for reproduction commands and evidence.

**Go header limitation:** Go 1.26 removes the entire received `Connection` header
when it contains `close`, before either `ReverseProxy` or its hooks see it.
Consequently arbitrary response headers nominated alongside `close` cannot be
identified reliably by this standard-library implementation. Known proxy
credential and standard hop headers are still explicitly removed. Nominated
headers are removed when their `Connection` metadata survives parsing. The Go
tests record this limitation; this is not a guarantee of complete arbitrary
response-hop filtering. No custom HTTP parser is introduced to work around it.

## Test-Only Executable

```sh
# From helper/; NEVER ship this executable.
GOTOOLCHAIN=local go build -tags=ts_omit_webclient -o bin/bridge-test-helper ./internal/testhelper
```

For a development `helperPath` override, resolve
`helper/bin/bridge-test-helper` to an absolute path from the repository root.
It accepts the identical stdin protocol and uses the production lifecycle,
state ownership, process isolation, and signal/EOF handling. Its fake node
immediately becomes ready and runs the **real pinned upstream**
`tailscale.com/net/socks5.Server` with random username/password authentication.
It also runs the production HTTP/CONNECT listener against the same simulated
dialer. It never starts tsnet or enrolls a node.

Test-only dialing accepts numeric loopback addresses, `localhost`, and
`upstream.test`; the latter two map to `127.0.0.1` with the requested port
unchanged. Bind a simulated upstream on `127.0.0.1:0`, then have the SOCKS client
request `upstream.test:<upstream-port>` through SOCKS or use the URL
`http://upstream.test:<upstream-port>` with the HTTP proxy. This proves the client
sends the name through the proxy instead of resolving it locally. No other hostname or non-loopback
IP is accepted by this test command. Production neither imports this simulator
nor offers an environment variable or flag to activate it.

Default verification covers shared control fixtures and frame limits, state
permissions/ownership/locking, lifecycle failures and cancellation through fake
nodes, structured enrollment notifications, executable signal/EOF disposal, and
the upstream SOCKS implementation's authentication, hostname/IP forwarding,
HTTP bytes, large/streaming uploads, SSE, concurrency, TLS transparency, and
tunnel teardown. It does not prove live enrollment, real MagicDNS resolution,
access-policy behavior, or runtime compatibility on other platforms. Live
tailnet verification must be explicitly opted into separately. HTTP tests cover
authentication before dialing, authority validation, application credential
preservation, header/trailer removal, streaming, no proxy replay/redirect follow,
end-to-end TLS/SNI, and active-connection teardown. If Bun 1.4.2 is installed,
the Go suite also runs `internal/testhelper/testdata/native-fetch.ts` against
local HTTP/HTTPS fixtures using native fetch with no JavaScript proxy adapter.
Select the project-pinned runtime from `.bun-version` on `PATH` before running
Go tests and confirm `bun --version` returns `1.4.2`. The project pin does not
upgrade global Bun; no global upgrade is required.

## Prior SOCKS Verification

Verified locally with `go version go1.26.2 darwin/arm64`: `go mod tidy`,
`go mod verify`, both executable builds, `go test ./...`, `go test -race ./...`,
and `go vet ./...` passed with `GOTOOLCHAIN=local`. Lifecycle tests also passed
100 consecutive runs; lifecycle/SOCKS tests passed 20 repeated runs. A three-
second protocol fuzz run executed approximately 49,000 inputs without failure.
Bun 1.3.14 launched the production executable with an incompatible version and
observed only the sanitized `PROTOCOL_ERROR` frame and nonzero exit.

State ownership is checked against a synthetic foreign UID in the non-root
test run; the actual `chown` case runs only when tests have root privileges.
The macOS `/var` alias test passed. Built-in SOCKS versus LocalAPI credential
wiring is checked against the pinned source, not through live node enrollment.
No live enrollment, real-tailnet policy/DNS tests, non-native runtime checks,
or package/tarball verification were performed as part of this helper-only work.

## Historical Dual-Proxy Verification

The following results predate the Bun 1.4.2 upgrade. They remain Bun 1.3.14
baseline evidence, not a claim that final new-runtime Go/package checks ran.

On Go 1.26.2 / macOS arm64, unfiltered `go test ./...` and
`go test -race ./...` passed: 55 top-level tests, 158 including subtests, across
eight tested packages, with no failures or skipped tests. The updated shared
dual-proxy fixture is included; no compatibility fallback is used.

`go vet ./...` and both native executable builds passed. HTTP proxy/lifecycle
tests also passed 20 repeated runs. The native Bun 1.3.14 test actually ran
(not skipped), exercising HTTP forwarding, independent credentials, opaque
HTTPS with original SNI, untrusted and mismatched certificates, incremental SSE,
cancellation, shutdown, and an unrelated direct fetch, without enrollment.

The raw-upstream end-to-end regression passed 20 repeated runs. For both 103
Early Hints and final responses, it confirms that an arbitrary nominated header
is removed without `close` but survives when Go has consumed `Connection: close`
metadata. Actual `Proxy-Authorization` fields are removed in both cases, and
the upstream never receives the client's local proxy credentials. This records
the qualified standard-Go behavior without a custom parser or workaround.
